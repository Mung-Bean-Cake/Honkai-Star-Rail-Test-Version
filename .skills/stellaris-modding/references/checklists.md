# 检查清单与最佳实践

## 一、新建 MOD 检查清单

- [ ] 游戏安装目录里确认目标版本，`supported_version` 写对（如 `v4.0.*`）
- [ ] `…/mod/<名字>.mod` 与 `…/mod/<名字>/descriptor.mod` 两个描述文件都存在
- [ ] 两个描述文件除 `path` 外内容完全一致
- [ ] `path` 使用正斜杠 `/`
- [ ] 缩略图命名为 `thumbnail.png`，放在 MOD 根目录
- [ ] 目录名拼写正确（`localisation` 不是 `localization`）
- [ ] `tags` 不超过 10 个

## 二、写内容时的检查清单

每条新内容都要问自己：

- [ ] 定义文件放对目录了吗？
- [ ] key 加了 MOD 唯一前缀吗？（避免与其他 MOD 冲突）
- [ ] 本地化写了吗？key 与定义文件里逐字符一致吗？
- [ ] 本地化文件是 UTF-8 **BOM** 吗？首行是 `l_<语言>:` 吗？
- [ ] 图标存在吗？在 `interface/*.gfx` 里注册 sprite 了吗？sprite 名唯一吗？
- [ ] 花括号配对吗？
- [ ] 事件 id 是 `namespace.数字` 且不含字母吗？
- [ ] 需要触发的事件写了 `is_triggered_only = yes` 和调用方吗？
- [ ] 事件里的选项至少有一个 `option` 吗？

## 三、发布前检查清单

### 功能

- [ ] 全新存档跑一遍完整流程，所有新内容都能正常触发 / 解锁 / 显示
- [ ] `error.log` 中搜索 MOD 前缀，无残留报错
- [ ] `game.log` 中无残留的 `log =` 调试输出（发布前删掉调试语句）
- [ ] 所有本地化在目标语言下显示正常，无裸 key、无 `?`、无乱码
- [ ] 所有图标显示正常，无缺失、无错位

### 兼容

- [ ] 与常见大型 MOD 同开测试（或至少在描述中说明兼容性）
- [ ] 没有覆盖任何原版文件；所有修改都在新文件里
- [ ] 没有使用过于通用的 key 名（如 `building_1`、`tech_x`）
- [ ] `descriptor.mod` 里的 `dependencies` 填正确

### 语言

- [ ] 至少提供 `english` 与目标语言两套本地化
- [ ] 本地化中无非法 Unicode 字符（`„ “ ‚ ‘ – ” ’ … —`）
- [ ] 中文文案换行使用 `\n` 或 `$TABBED_NEW_LINE$`，排版正常

### 性能

- [ ] 事件默认 `is_triggered_only = yes`，只有确实需要轮询的才用 MTTH
- [ ] 所有 `every_*` 遍历都带 `limit`
- [ ] 没有在每日 `on_action` 里做重计算
- [ ] 巨型事件链做了阶段化，避免一次性大量计算

### 打包

- [ ] 删掉 `.backup/`、`.idea/`、`.vscode/`、`*.autosave`、临时文件
- [ ] 删掉 `descriptor.mod` 中的 `path` 行（如果这是要上传的版本）
- [ ] 版本号已更新（`descriptor.mod` 的 `version`）
- [ ] 更新说明写好（更新日志是玩家最在意的东西）

## 四、兼容性最佳实践

1. **绝不覆盖原版文件**。用新文件定义同名对象来覆盖，或在 `localisation/replace/` 里覆盖文本。
2. **所有 key 加唯一前缀**。前缀建议用 MOD 缩写，如 `hsr_`、`dot_`。
3. **`on_actions` 用独立文件**，不要改 `00_on_actions.txt`。用 `zz_` 前缀让文件排在后面。
4. **`defines/` 覆盖用 `00_` 前缀**（字母序要在原版文件之前）。
5. **静态修正不要凭空新建重复 key**，否则会覆盖别人的。
6. **`dependencies` 声明真实依赖**，别滥用（会强制玩家装一堆东西）。
7. **提供一个"无覆盖模式"开关**（若 MOD 提供自定义设置界面，可让玩家关掉冲突部分）。
8. **发布兼容性补丁**而不是硬改主 MOD——补丁 MOD 加载顺序排在主 MOD 之后。

## 五、性能最佳实践

1. **`is_triggered_only = yes` 是默认选项**，用 `on_actions` 挂钩而不是轮询。
2. **MTTH 谨慎使用**，官方明确因性能问题不推荐。能用事件钩子就用钩子。
3. **`every_*` 遍历必须加 `limit`**，全银河遍历是性能杀手。
4. **条件顺序优化**：`AND` 里最可能为假的放前面，`OR` 里最可能为真的放前面。
5. **减少每 tick 执行的脚本量**：把复杂的每日判断改成"触发器触发 + 缓存变量"模式。
6. **用 `script_profiler` 定期体检**。
7. 避免在 `on_monthly_pulse` 之类的全局脉冲里对所有国家/行星做重计算。

## 六、代码可读性

1. 文件头写一行注释说明用途与作者。例：`# 崩坏星穹铁道 MOD - 事件定义`
2. 按功能分文件，不要把所有东西塞进一个 `zz_all.txt`。
3. 缩进用 tab，保持与其他 `common/` 文件一致的风格（Paradox 原版用 tab）。
4. 复杂逻辑抽成 `scripted_triggers` / `scripted_effects`。
5. 用 `#` 注释解释"为什么"而不是"是什么"。
6. 数值常量抽到 `scripted_variables/`，便于全局调整。

## 七、常见发布平台

| 平台 | 说明 |
|------|------|
| **Steam 创意工坊** | 主流。需上传工具或第三方脚本；`remote_file_id` 会自动写入描述文件 |
| **Paradox Mods** | 官方平台，跨平台可用（含主机版兼容） |
| **GitHub** | 源码托管与协作；建议同时提供 Release 压缩包 |
| **MOD 汉化 / 交流群** | 中文 MOD 生态常见分发方式（QQ 群等） |

发布时注意：**不要把 `path` 行写进上传的 `descriptor.mod`**——那行是本机路径，对其他玩家无意义。

## 八、出问题时的排查顺序

1. 看 `error.log`，搜 MOD 前缀。
2. 检查文件是否放在正确目录（拼写！）。
3. 检查本地化编码与命名。
4. 检查花括号配对与 namespace/id。
5. 检查是否与已有 MOD 冲突（只加载本 MOD 单独测试）。
6. 用控制台 `event <id>` / `trigger <...>` 手动验证脚本片段。
7. 二分法：注释掉一半代码，看问题是否消失。
